# FS-03 — Project, media and recovery

**Status:** Draft. **Dependencies:** project command model, media identity, storage protocol. **PRD:** §§8, 18, 21.

Before the first public beta, projects may require the current development
schema. Earlier development schema notes below record implementation history,
not a compatibility promise. PM-07 applies once a schema has shipped publicly.

## Functional contract

- **PM-01** Import supports WAV, AIFF, FLAC and MP3. Default import copies the original encoded bytes into managed assets. Explicit external linking records source location, stable identity and missing-file status. Decoding and analysis never overwrite the original.
- **PM-02** Collect-and-save copies all linked media into managed assets, verifies identity and produces a self-contained project. A partial failure leaves the previous valid project and original links intact.
- **PM-03** Manifest, plugin state, tracks, clips, tempo and meter maps, project sample rate, automation, routing, manual analysis corrections and media identities survive save/reopen. A rate-change generation records the new nominal rate and converted elapsed anchors. Processing cache files are optional and may be deleted without changing project meaning.
- **PM-04** Save and autosave publish only complete generations. `CURRENT` points to the last explicit save; `AUTOSAVE` points to a separate complete generation. On interruption, opening validates references and reports incomplete work. A post-pointer-rename directory-flush failure reports uncertain durability rather than success or guaranteed rollback.

The desktop schedules autosave every two minutes by default. The user can choose Off, 30 seconds, two minutes or five minutes from the project library; the persisted setting also accepts any interval from 15 to 1800 seconds. Autosave captures only a dirty immutable project revision and writes `AUTOSAVE` on a worker. A source awaiting its same-writer receipt is deferred until publication completes; external links are verified on that worker before pointer publication. Explicit Save, media publication, revision naming and autosave share a nonblocking writer gate, so a competing control action reports a conflict for retry rather than waiting on filesystem I/O in the UI or audio callback. Project switching is deferred while the worker is active; close retries when it completes. No stale result is installed in the next project. Autosave failure and uncertain durability are visible and do not advance `CURRENT` or clear the unsaved state.

Routine instrument and plugin editor commits capture an immutable, media-complete revision on the UI thread and publish `CURRENT` on a worker after a short coalescing delay. A newer edit remains dirty until its own generation commits; a stale worker may never regress `CURRENT`. The UI distinguishes accepted model intent from committed disk state and reports save failures without discarding the edit. Edits that introduce media receipts or change external links use their dedicated verified publication path. Explicit user Save, relink, import, project transition and named revision operations retain their own publication rules; an active editor save must finish before project ownership changes.
- **PM-05** Recovery presents the validated last explicit save and latest valid autosave with timestamps and differences sufficient for a user choice. If the explicit-save pointer is unreadable, validated complete generations are offered for choice without silently declaring one the saved state. Named revisions remain selectable.
- **PM-06** Missing media is shown by stable identity, expected metadata and last known path. Relinking validates candidate media before changing references, preserves all clip edits, and can relink multiple matching uses atomically.
- **PM-07** For publicly released project schemas, versioned migrations make a pre-upgrade backup, validate output and allow rollback on failure. Unsupported future major versions do not rewrite the project.
- **PM-08** Malformed manifests, oversized state blobs, invalid paths and corrupt media metadata produce bounded errors and do not execute unintended file operations.
- **PM-09** Managed-media import copies and verifies large source files on a worker while the project control sequencer remains available for edits. Beginning import does not change the project model. Completion rejects a changed project revision or writer, validates the source and IDs, and then creates one undoable source/track/clip revision. Cancellation, validation failure or a dropped completion removes only its private staging file. If the accepted revision cannot be saved, it and its same-writer source receipt remain available for a save retry.

## Component contract

All persistent object IDs are independent of file paths. A project generation under `state/generations/` records schema version, parent generation, monotone project revision, asset references and checksums. `state/CURRENT`, `state/AUTOSAVE` and named revision pointers refer only to complete generations; the manifest lives inside each generation. Writes use durable staged assets, a new generation and an atomic pointer advance after data and directory flush. The detailed Linux syscall sequence, SHA-256 dependency choice and crash matrix are in ADR-0004; syscall error mapping and the filesystem qualification matrix remain G4 review items. Project-managed paths are contained under a held project root and never follow symlinks; external links are explicit typed references. Cache paths never appear as essential asset references.

Commands and persistence use a canonical snapshot serializer. Undo history is session-scoped and not persisted; named revisions are the cross-session return mechanism. The current project state, manual choices and named revisions may not be lost. Plugin placeholders preserve opaque state even when no plugin is installed. Media hashes are calculated off the audio thread.

Schema 1.12 adds `source_tempo_reviews` to essential project state. Each record is bound to one immutable source ID, with generated BPM/confidence and beat suggestions separate from optional corrected BPM and user beat markers. Older 1.0–1.11 manifests reopen with no reviews. A cache clear or corrupt analysis cache may regenerate derived suggestions but cannot discard the manifest's user correction or markers. The project model rejects stale analysis revisions and validates marker bounds, order and provenance before publication.

Schema 1.14 adds `source_key_reviews` as a separate essential per-source array. A review holds optional generated tonic/mode (C=0 through B=11; major/minor), positive confidence in (0,1] for a detected key, at most three distinct compatible suggestions labelled relative, dominant or subdominant, and an optional user correction. Each label has the corresponding pitch-class and mode relationship to the detected key. An unknown generated key has zero confidence and no compatible suggestions; a correction may still exist. Reanalysis replaces only generated fields and is accepted only for the exact captured project revision, encoded-source SHA-256, sample rate and frame count. Source removal removes its review; undo restores it. Older 1.0–1.13 manifests reopen with no key reviews. The project model owns these minimal typed values, independent of the analysis worker. The application adapter translates the worker's key result into this command, including explicit unknown, and must use the captured source identity, not the current display label. Cache deletion cannot erase a correction. Unsupported future schema and malformed key records fail before project publication; interrupted 1.14 saves leave the prior valid generation accessible.

Schema 1.15 adds a required typed `location` to each source: `managed`, or `external` with a bounded absolute UTF-8 `last_known_path`. Older 1.0–1.14 sources migrate as managed. An external path is not a managed asset or cache key; adding a new link verifies its encoded SHA-256 and decoded metadata from a pinned regular file without copying or modifying it. Reopening retains source and clip IDs and reports a missing or damaged external path. A previously saved link can remain in later project edits while its file is absent. The initial read model checks file presence, regular-file type and encoded length; full content verification is required before media consumption. The path is display/recovery state, not source identity. Collect-and-save and UI flow remain separate PM-01/02/06 work.

Schema 1.17 adds a required `fades` record to each audio clip. It stores finite `in_fraction` and `out_fraction` values whose sum is at most one, plus `linear` or `smoothstep` curves for each edge. Older manifests reopen with zero-length fades; an incomplete, malformed or unsupported fade record fails before project publication. Fade settings are clip-instance project state, never derived waveform/cache data. Save, undo, named revisions and collected copies retain the settings.

Schema 1.16 adds a required boolean `muted` to each track. Older tracks reopen unmuted. Mute is durable project intent and one undoable command; the active render graph may lag and must report that status. Removing a track is one undoable command and fails atomically if another track still routes to it. The master is a logical path outside the saved track array.

Schema 1.18 adds a required boolean `soloed` to each track. Earlier saves reopen unsoloed. Solo is a durable, undoable routing edit; save/reopen and active-graph revision reporting follow the same contract as mute.

Schema 1.19 adds finite `level` in 0..4 and `pan` in -1..1 to each track. Earlier saves reopen at unity level and centered balance. Missing or malformed fields reject before publication. Both settings are durable project intent and one combined undoable routing command.

Schema 1.20 adds finite `master_level` in 0..4 to project state. Earlier saves reopen at unity. The value is an undoable post-master-insert output gain, applied to both channels after the master limiter and to master and processed-stem exports. A missing or invalid field in a 1.20 manifest rejects before publication.

Schema 1.24 adds a required `processing` record to each audio clip: finite pitch shift in -12..12 semitones, a formant-preservation choice and at most 4,094 ordered reviewed warp markers. Each marker stores an absolute source frame and a clip-local target offset in the clip's placement timebase. Earlier saves reopen with neutral pitch, formant preservation selected and no reviewed markers. Missing, malformed, out-of-range or colliding markers in a 1.24 manifest reject before publication. These settings are essential clip-instance state; the derived rendered audio is disposable cache data.

Schema 1.28 adds a required `warp` record inside each audio clip's `processing`:
- `mode` and `mode_overridden`;
- `beats` {`loop`, `envelope`};
- `tones` {`grain_ms`};
- `texture` {`grain_ms`, `flux`};
- `complex_pro` {`formants`, `envelope`}.

Pitch widens to finite −48..48 semitones. Saves from 1.24–1.27 reopen with their pitch, formant choice and markers exactly, mode `complex`, not overridden, and default parameters. New clips may instead start with a verified source-classification mode; later automatic selection is an explicit undoable revision and never overwrites a manual mode. A 1.28 manifest with a missing, extra, unknown or out-of-range warp field rejects before publication. The fields are rate-independent clip-instance intent; quality tier and rendered audio are not saved. See FS-05 and ADR-0026.

Schema 1.25 permits a `native_convolution` effect insert on a track or master chain. Its saved state contains a managed WAV source ID and immutable encoded SHA-256, byte length, sample rate, channel count and frame count, plus wet level and a nonzero settings generation. The IR identity must match a managed source record exactly. Admission is limited to mono or stereo WAV, 44.1/48/88.2/96 kHz, at most two seconds and 16 MiB encoded bytes; wet is finite in 0..1. Missing or malformed identity and settings reject before project publication. An existing source record and insert identity survive loading when the asset file is missing, with a missing-asset diagnostic; saving that incomplete project currently fails the store's managed-asset integrity check. Changing settings is one undoable command and increments generation. The optional PFFFT build admits one active convolution insert in native offline master and processed-stem export, after checking the managed IR descriptor, checksum, metadata and preparation budget. Insert order and the finite IR tail are rendered; missing or changed IR media fails before output publication. Builds without PFFFT, live playback and VST3-specific export still reject the saved slot explicitly, including when bypassed, rather than dropping it from the signal path.

Schemas 1.26 and 1.27 added the sampler's envelope and low-pass cutoff; schema 1.44 removes the sampler instrument source and its `sampler_level` control key ([ADR-0063](../decisions/0063-crate-chop-sampler.md)). The former text follows for history only.

Schema 1.27 adds `lowpass_cutoff_hz` to sampler patch version 3. Zero bypasses tone shaping exactly; enabled values are finite 20–20,000 Hz. Schema 1.26 version-2 and older version-1 patches reopen with cutoff zero, preserving their sound. A 1.27 patch requires the field and rejects malformed, missing or extra values before publication. A project sample-rate change keeps the cutoff in Hz and prepares a new coefficient at the new rate.

Schema 1.26 adds attack, decay, sustain and release to sampler patch version 2. Duration fields are unsigned project-rate frames limited to 20 seconds at that rate; sustain is finite in 0..1. A schema 1.0–1.25 version-1 patch loads with instant attack/decay, full sustain and its original 64-frame release, then saves in the new shape. Missing, extra, malformed or out-of-range fields in a 1.26 manifest reject before publication. A project sample-rate edit rescales stored durations through the shared sample-coordinate converter as part of the same atomic, undoable revision; if a positive duration would round to zero, the edit fails rather than silently erasing that stage.

Schema 1.43 (ADR-0059) adds three required fields to each track: `note_effects` (MIDI effects before an instrument track's source, sharing the effect slots' id namespace), `macros` (up to eight knobs whose mappings copy their parameter's domain; a `macro` lane target expands into lanes on the mapped parameters) and `frozen` (null, or a stereo project-rate managed WAV render with its first frame and rendered revision). Commands that would change what a frozen track rendered are refused until it is unfrozen.

Schema 1.44 ([ADR-0063](../decisions/0063-crate-chop-sampler.md), [spec 09](09-crate-sampler.md) §1.1) adds `regions` to a built-in synth's document: `[{slot, media, start_frame, tag, name}]`, omitted when empty (an empty array is rejected). The model checks structure only: at most 128 regions, unique slots, each `media` a media slot of the same document, `start_frame` strictly increasing within one media in vector order, tag at most 16 and name at most 64 UTF-8 bytes. The engine checks meaning. The sampler (`"kind": "sampler"`) is removed with no migration. Only 1.44 manifests load.

Schema 1.45 ([ADR-0081](../decisions/0081-clay-note-editing.md)) adds a required `clay` field to each audio clip: null, or `{mode: "melodic"|"polyphonic"|"percussive", analysis_version, ops: [{kind: "split"|"join", note, other, frame}], edits: [{note, voice, pitch_cents, modulation, drift, formant_cents, gain_db, muted, placement: null|{start, end}}], key: null|{tonic, mode}}`. Frames are source frames at the source rate. The model checks structure and the bounds in `clay_dsp/limits.hpp`: at most 4096 ops and 4096 edits, one edit per (note, voice), voices up to 8, a placement both-or-neither with start before end, and the current `analysis_version`. Only 1.45 manifests load.

`RelinkSource` changes only an explicit external link's last-known path in one undoable model revision. It requires the captured project revision and exact previous path; stale or managed-source commands fail without mutation. The immutable encoded identity, source ID and clip references do not change. Before a newly changed link is saved, the store verifies regular-file type, full encoded hash and decoded metadata at the candidate path, including when that path also appears in a named revision or autosave. It checks the pinned file version and path again before publishing the save pointer. Verification failure leaves the last valid `CURRENT` and the accepted in-memory model edit available for correction, undo or retry. External files can change after publication and must be fully verified before consumption. Collect-and-save remains separate PM-02 work.

`ProjectSession::begin_external_source_relink` captures the exact revision, old location and immutable source identity. A move-only task checks the candidate's full hash and decoded metadata on a worker, yielding a proof bound to one store instance, source record, candidate revision and file version. `finish_external_source_relink` requires stopped transport and rejects stale completions before changing the model. It applies one undoable command, then saves using the proof; store publication reopens the named path and checks its version again. A save failure leaves the in-memory edit and proof for a same-path worker re-verification or retry. Session `save()` refuses an unsaved external path without a matching worker proof, including paths reached by undo/redo. A named-revision restore that changes an external path is rejected before model mutation until worker verification is available for that workflow. The relink-specific final manifest and directory fsync still run on the control thread and can stall on a slow filesystem; unlike routine editor saves, relink needs its external proof at pointer publication. The QML relink flow is a separate UI integration slice.

Live audio and synth media preparation use `ProjectStore::open_verified_source` on the preparation worker. Managed source handling is unchanged. For external links, the store requires an exact typed record in saved `CURRENT`, opens the named regular file without following a symlink, checks the full encoded SHA-256 and decoded sample rate/channel/frame metadata, then returns the pinned verified descriptor to the reader. Worker preparation accepts a stop token for cancellation during full hashing and between clip/decoder reads. Cancellation, missing files, same-size damage and an unsaved/stale link fail before decoder consumption or graph start; source and clip IDs remain intact for relinking. The caller must compare its captured project revision again before installing worker output. The synchronous convenience playback start refuses external sources so that path cannot hash large linked media on the UI thread. The project-local asset directory is never used as an external-link fallback.

`collect_and_save_copy` is a worker-only PM-02 operation on a captured explicit save and its named revisions. It verifies and stages every source referenced by either the captured save or a named revision into a private sibling project, retains source and clip IDs and saved edits, converts copied locations to managed, recreates the named revision points, then publishes the new project name without replacing an existing destination. If revision history is damaged, the copy fails explicitly rather than silently dropping a return point. An unavailable historical external path may be satisfied by the same immutable source identity at a newer saved path. A failed or cancelled copy leaves the original project and its external links untouched and does not publish a destination. The Project Media action saves first, captures that revision, starts a cancellable worker, chooses an unused name in the default project library and refreshes the list on completion. The worker rechecks the current generation and named revision listing immediately before publication; a change observed by that check fails explicitly. A source save racing after the final check can leave a valid copy of the captured earlier generation, but later edits are never silently included in it. Autosave remains recovery state in the source project and is not a named return point in the collected copy. The panel reports media-source count progress, saving, cancellation, success and failure states; byte-level progress and a broader filesystem fault-injection matrix remain open.
