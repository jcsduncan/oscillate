# FS-07 — UI, diagnostics and release qualification

**Status:** Draft. **Dependencies:** application services and read models. **PRD:** §§6, 19–23.

## Functional contract

- **UQ-01** First run offers device setup, a sample project, starter content and a route to core workflow guidance. The arrangement, mixer, automation, piano roll, browser, project/media and processing/diagnostics panels are accessible from one workspace.
- **UQ-02** Panels resize, show/hide and restore saved layouts. UI works at 1080p and 4K/high DPI. Core commands have keyboard access, visible focus, accessible names and non-colour status indicators. Formal screen-reader certification is not a v1 gate.
- **UQ-03** Contextual tooltips and searchable documentation explain controls and limitations. Error messages identify the affected device, media, plugin, route or job and offer an action when available.
- **UQ-04** Diagnostics stay local by default. Crash/performance sharing requires explicit opt-in. A user reviews a redacted diagnostic bundle before sharing. Update notices never install without a user action; stable/beta channels and a documented rollback path per distribution are present. Native package rollback is handled through the package manager; AppImage rollback can use a retained earlier image.
- **UQ-05** Launch usability sessions use representative novice and experienced users completing the primary production workflow. Task completion, time, and critical errors are recorded against thresholds set before testing; a blocker that prevents a completed project blocks release.
- **UQ-06** Release qualification includes functional, 32-track performance, integrity/recovery, audio correctness, plugin compatibility, accessibility/usability, licensing/SBOM and supportability gates. Known limitations are published with the release.
- **UQ-07** The arrangement shows bar and beat references through empty audio, instrument and bus rows at every supported zoom and scale. Selecting a track, bus or master exposes its source → ordered effects → output path in a resizable bottom device dock. A compact card offers relevant live controls, bypass, saved-versus-active status and access to a larger editor. Effects reorder by drag and keyboard; a right context panel opens for detailed work and closes without hiding the device dock. A group bus heads its members in the track list: they sit indented directly under it on a rail in its colour, in saved order, without changing the saved track order. A group bus folds from its chevron, hiding its members' rows and showing their clips as one dashed outline on its lane; the fold is kept per project with the row heights. Return buses sit in a returns section at the bottom of the list, each naming the tracks whose sends feed it and its first effect; a track's sends show as pills in their returns' colours. The master remains pinned at the bottom. Native and VST3 effects share chain placement and status semantics. A chain edit shows saved versus active-graph status when it cannot apply immediately.
- **UQ-08** Every project shows the master as the final pinned track row. A subdued add-track row is pinned directly above it, below the scrolling ordinary and bus tracks, including in an empty project. Its plus button opens keyboard-accessible choices for an instrument, audio import, group and return. Every newly created track, whether from that menu, a dropped local audio file or a verified browser instrument, is appended immediately above the add row. The verified instrument track and insert are one undoable edit; failed verification creates no track. Holding and dragging a track row (or the selection it belongs to) moves it and sets its routing as one undoable saved edit, preserving its ID, clips and insert chain: dropped inside a group bus's bracket, between its header and its last member, it feeds that bus at the open slot; on the bus header, it becomes the bus's last member; anywhere else, it goes to the master at that place. A chip names the destination while dragging. A bus is never dropped into a bus; that drop is refused with a status message. The viewport scrolls while the pointer stays near its edge, and the add row, returns and master cannot be moved. Dragging a track's lower edge changes its height in the controls and arrangement together, expands its waveform and automation viewing area, and restores that height on reopening the project. The master and add row remain visible and aligned while ordinary tracks scroll.
- **UQ-09** Built-in effects and instruments use a coherent, polished device-panel system with readable knobs, sliders, response or envelope displays and useful meters. Track and master devices share panel placement and chain behaviour. Large native and VST editors use one modeless floating host: it can move within the DAW, remains open while the user edits timing or navigates elsewhere in the workspace, and captures input only within its visible frame. Selecting another track does not silently retarget an open editor. Continuous controls respond during playback when the engine supports their change; their displayed values and audible state agree. A control with a genuine processing limitation explains the limitation and shows saved versus active status. Layout, labels, focus, value entry and hit targets remain usable at 1080p and 4K/high DPI. Reference DAWs inform workflow and clarity, while the visual design remains original to this product.
- **UQ-10** Project BPM and meter stay visible beside transport and edit the authoritative initial timing events through validated, undoable commands; changing the BPM preserves its existing ramp shape. The optional project key/scale is durable musical metadata and never silently transposes sources, clips or notes. No global value is inferred from a source analysis result without explicit user acceptance.
- **UQ-11** One searchable device browser groups bundled instruments and effects separately from VST3 entries, shows the insertion target, and never advertises an action the current project path cannot accept. A VST3 compact card is built by the host from exported parameter metadata. Its larger view opens the plugin editor when supported and otherwise offers a labelled generic parameter view.
- **UQ-12** Selecting a MIDI clip opens its piano roll in the bottom dock so track rows, the ruler and arrangement clips remain visible. Devices and clip details remain available as adjacent tabs. Grid division and Quantise are explicit, keyboard-accessible controls; pitch scrolling reaches the full MIDI range without changing saved notes.
- **UQ-13** A drum instrument with a verified note map offers named drum lanes in that same MIDI dock and an explicit Piano/Drums toggle. The lane labels come from the instrument's registered pad definitions. Notes outside the map are counted and reachable through All Notes; switching views never changes project data.
- **UQ-14** Arrangement clips select as a group across tracks. While the arrangement has the keyboard, Ctrl+A selects every audio and MIDI clip on every track; while the piano roll has it (a click in its grid, or opening a clip's notes), Ctrl+A selects that clip's notes instead. Ctrl+A in the arrangement also lets go of selected notes. Shift- or Ctrl-click adds or removes one clip, a box dragged on empty lane space selects every clip it touches, and a click on empty lane space clears the selection. Selected notes come first: Escape lets go of them, then of the clips, and Delete removes them rather than the clips. Dragging any selected clip moves the whole selection by the same snapped offset, each clip on its own track unless the drag changes rows; the arrow keys move it one beat, even from a focused clip outside it. A group move is one undo step and is refused as a whole when any clip would start before bar 1 or land on the wrong kind of track. Delete, copy, cut, paste and duplicate act on the whole selection.

## Component contract

Qt types stop at the UI/application boundary. UI dispatches commands and observes read-only revisioned view models; it cannot mutate the audio graph. Expensive waveform rendering, plugin scanning and analysis use asynchronous services. A status view distinguishes accepted project state, pending engine application and rejected graph update. Diagnostic events carry stable category and correlation ID, with paths redacted on bundle export.

The production UI is a custom Qt Quick/QML shell under [ADR-0022](../decisions/0022-qt-quick-ui-direction.md). Qt Widgets is linked only for native file dialogs. The module inventory and distribution review extend to Quick/Qml/Controls before packaging. The revision status view must identify accepted project state, pending engine application, active playback state and failed changes, with retry or undo. Custom controls must expose accessible names and keyboard interactions as they are added, rather than a final accessibility pass.

Quick playback consumers use machine-readable phase, application state, model revision, active graph revision and plugin-fault fields for decisions. The human-readable transport message is presentation text only; changing its wording must not change plugin availability or stopped-state UI behaviour.
