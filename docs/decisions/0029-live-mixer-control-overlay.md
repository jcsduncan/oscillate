# ADR-0029 — Bounded live mixer-control overlay

**Status:** Implemented for admitted channel controls and existing send gains.
**Date:** 19 October 2026.  
**Requirements:** ER-01, ER-09, AM-05.  
**Affected interfaces:** `RoutedMixerPublisher`, `RoutedMixer`, `PreparedRouteGainBlocks`, `ProjectRoutePlan`. No project schema or dependency change.

## Decision

A same-topology mixer-control edit can publish a new graph revision at the next callback boundary without holding transport. The control producer prepares a complete, topologically ordered `RoutedNodeControl` vector from the saved track levels, pans and effective mute mask. Solo is projected through the existing upstream/downstream route traversal; explicit mute wins. The publisher validates node identity, gain bounds and revision, then offers one immutable candidate. The callback fills the **currently active source revision**, adopts the candidate, and updates post-insert node gains on the existing mixer. Its source cursor, routing delays and other mixer storage are not rebuilt. A changed gain, pan or mute ramps from the current audible value to its target over at least 64 rendered frames; a newer admitted update begins from the intermediate ramp value.

The fast path admits only settled graphs with no dry insert, no active predecessor tail, and processors that explicitly implement the revision-independent control-overlay opt-in. Empty processor slots are safe by construction. It refuses a changed node whose prepared gain source has channel-level automation. An unknown gain-source implementation is treated as bound everywhere. Send automation on unrelated edges does not block a channel-control edit. These restrictions avoid silently overriding automation or changing a revision-bound plugin instance. A refusal leaves the prior graph audible and the saved edit inactive; the application must expose that status and may use its existing held-graph route when safe. An active revision receipt, rather than the prepared candidate, is the evidence that the control is audible.

The control candidate carries the source revision separately from its graph revision. Later callbacks continue filling the same source bank; a subsequent source-only edit can publish its own bank. This avoids requiring a media worker to build a duplicate source bank for a mixer knob change. All vectors and validation are control-side; the callback uses bounded loops, no allocation, lock, wait or I/O. Muting ramps the post-insert output toward zero while other routes continue normally. It does not stop processors or erase their history; broader processor admission still needs explicit revision-reuse qualification. A 64-frame ramp limits abrupt amplitude steps but does not prove click-free output for every waveform or gesture.

An existing send-gain edit uses the same settled-graph handoff with a complete edge-ID/gain projection. The project diff must leave send IDs, endpoints, purposes, target slots, tracks, processors, automation and timing unchanged. Only mapped saved send gains may differ. The publisher rejects an incomplete or mismatched edge projection and refuses a changed edge bound to send automation; unknown gain sources are conservatively treated as bound. At the callback boundary, an admitted edge gain ramps from its current audible value over at least 64 frames, including a newer value offered during an unfinished ramp. The active mixer, source bank, processor instances and compensation lines are reused. Topology edits and automated sends retain their guarded publication path and explicit saved-versus-audible status.

## Evidence and limits

Focused 64/128-frame publisher and application tests exercise mute, unmute, level, pan and send-gain changes during continuous playback. They assert active revision, zero counted callback allocations, no inserted silent block and final gain. Routing tests verify solo projection, node and edge ordering, and automation binding. Revision-sensitive processor and bound or unknown automation routes refuse the fast path without displacing the old graph. Changed send identity or endpoint also refuses it. A stateful opt-in delay fixture and live native processor tests verify that processor and compensation history continue across admitted controls. Unqualified processors, topology-changing and overlapping edits remain under their guarded publication policies.
