# VST3 Qt editor bridge slice

**Status:** Standalone host/UI attachment contract; PI-03 and G8 remain open.

`oscillate_plugin_ui` is built when both Qt Quick and the pinned VST3 SDK are enabled. It owns a Qt UI-thread `IRunLoop` for readable file descriptors and repeated timers, a VST3 `IPlugFrame` resize service, and a native `QWidget` X11 window. The application has not yet connected this component to a project insert or a generic parameter panel. No third-party editor compatibility is claimed.

`Vst3EffectHost::create_editor_view()` returns one opaque lease at a time and a specific probe status. The host and loaded module must outlive the editor attachment. The attachment calls `setFrame`, `attached`, `removed`, `setFrame(nullptr)`, and releases the view in that order. Failed attach attempts get best-effort `removed()` before the window is destroyed. The frame accepts resize requests between 32 and 4096 physical pixels per dimension and defers `onSize()` requested during `attached()` until attachment succeeds. The run loop is bounded to 64 FD handlers and 64 timers per editor; duplicate handlers/FDs, invalid intervals and calls off the Qt owner thread are rejected. Editor lifecycle is UI-thread work, never audio-callback work.

The X11 route requires Qt's `xcb` platform and an actual native window ID. XWayland uses that route when Qt is running under `xcb`. A native Wayland Qt platform returns `native_wayland_unavailable` before creating a view. An offscreen or other Qt platform returns `no_native_window`. Missing controller, missing view, unsupported platform, unavailable host, frame rejection, failed attachment and caught C++ plugin exceptions have distinct fallback statuses. Native plugin crashes remain outside C++ exception containment.

Local contract evidence: synthetic VST3 view attachment on the current X11 display; timer dispatch while attached; ordered detach, view release, failed frame/attach/throwing paths; offscreen fallback; host single-lease lifecycle; FD and timer registration and UI-thread rejection. The X11 test is added only when `DISPLAY` is set at configure time. These fixtures do not demonstrate a real plugin GUI, Wayland/XWayland interoperability, host/project integration, keyboard/focus behaviour, DPI correctness, or safe editor teardown for plugins that violate the VST3 lifecycle. PI-03 still requires two versioned reference plugins on Ubuntu 26.04 in X11 and Wayland sessions, repeated open/close with playback, and generic parameter fallback integrated into the app.

The focused GCC coverage run exercised 186/220 `plugin_ui` executable lines (84%). The remaining paths include uncommon SDK exceptions, native window creation failure, native Wayland, and host probe statuses beyond the bundled no-view fixture; they remain explicit follow-up evidence rather than being excluded from coverage. The focused ASan/UBSan run passed. For the X11 sanitizer test only, LeakSanitizer was disabled because the host Qt GTK/fontconfig platform theme retained process-global allocations; the offscreen sanitizer test ran with leak detection enabled.
