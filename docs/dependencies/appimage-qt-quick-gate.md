# Qt Quick AppImage distribution gate

**Status:** Earlier ELF and QML load inventory, 15 October 2026. The [release AppImage](release-packages.md) now records a Quick and VST3 scanner payload without the codec adapter, an exact copied-library inventory, pinned runtime/tool and offscreen smoke; licensing and portability gates remain open. This earlier inventory supplements the [Qt runtime inventory](qt-quick-runtime.md), [release packages](release-packages.md) and [distribution review](distribution-sbom-review.md). The inventory below is for the older `BUILD_TESTING=OFF` Ubuntu 26.04 x86-64 Quick binary at `build/package-release2/apps/daw_quick/oscillate` (SHA-256 `4dfc383f0abc0a17a36536195d16732715b79b51bde7366b7fb7fa566ae37546`); it is not the newer AppImage payload inventory.

## Observed Qt closure

`readelf -d` reports no `RPATH`/`RUNPATH`. The executable directly needs `libQt6Core.so.6`, `libQt6Gui.so.6`, `libQt6Qml.so.6`, `libQt6Quick.so.6` and `libQt6Widgets.so.6`. It does **not** need `libQt6Test.so.6` in this configuration. Local `ldd` adds `libQt6QmlMeta.so.6`, `libQt6QmlModels.so.6`, `libQt6QmlWorkerScript.so.6`, `libQt6Network.so.6`, `libQt6OpenGL.so.6` and `libQt6DBus.so.6`. These resolve to Ubuntu 26.04's Qt 6.10.2 packages on this host. The executable also needs PipeWire, libsamplerate, libsndfile and OpenSSL Crypto; their full transitive closure must be inventoried separately when an AppDir exists.

An offscreen `--create ... --smoke` with `QT_DEBUG_PLUGINS=1 QML_IMPORT_TRACE=1` returned `revision 4, 1 tracks; clip delegates: 1`. It **loaded** `platforms/libqoffscreen.so` and `platforminputcontexts/libibusplatforminputcontextplugin.so` from the host. It resolved `QtQuick`, `QtQml`, `QtQml.Models` and `QtQml.WorkerScript` `qmldir` resources at `:/qt-project.org/imports/...`; the trace did not load separate `.so` QML plugins. The app's three QML source files and four starter WAV files are compiled into its QRC. This result is specific to the local Qt build and offscreen run; `QML_IMPORT_TRACE` on the final image must decide whether external QML module files are needed. [Qt requires deployed QML modules and suitable platform plugins](https://doc.qt.io/qt-6.10/deployment.html) when they are not otherwise built into the delivered runtime.

The system has `libqjpeg.so`, `libqgif.so`, `libqsvg.so`, XCB EGL/GLX integrations and multiple Wayland client graphics/shell/decorations, but their inclusion remains unproven. The Qt [Linux deployment guidance](https://doc.qt.io/qt-6.10/linux-deployment.html) identifies `xcb` and `qt.conf` plugin paths. [AppImage recommends excluding certain base and hardware-specific libraries](https://docs.appimage.org/introduction/concepts.html); an automated dependency copier still needs a reviewed inclusion/exclusion list and a target-machine test.

## Licensing and replacement contract

The five direct Qt modules have an [LGPLv3 route](https://doc.qt.io/qt-6.10/licensing.html), as do the normal transitive Qt modules subject to their exact package/file review. Qt's list separately identifies GPL-only modules, including Qt Qml Compiler and Wayland Compositor; neither is evidenced in this binary. The [Qt obligations page](https://www.qt.io/development/open-source-lgpl-obligations) requires the applicable licence and prominent Qt-use notice, complete corresponding Qt source (including modifications) or a project-controlled written offer, and a way for recipients to replace/relink the libraries and run the result, with installation instructions. A link to upstream source alone does not close the source-offer duty. Examine Qt's [third-party code and per-release SBOM](https://doc.qt.io/qt-6.10/licensing.html#software-bill-of-materials) against the exact shipped build.

For an AppImage, the proposed route is dynamically linked Qt `.so` files under `AppDir/usr/lib`, a launcher and `qt.conf` that choose that same tree's plugins, and published instructions to extract the image, replace an ABI-compatible Qt library or plugin, and run the modified AppDir. [AppImage documents extraction as producing a valid AppDir](https://docs.appimage.org/user-guide/run-appimages.html). The replacement test must show the **modified** library loaded under both X11 and Wayland; a startup that silently chooses host Qt fails. Record the same test for LGPL Qt platform/QML plugins actually bundled. A read-only mounted SquashFS does not itself prove that recipients can replace components; extraction and documented execution/repacking are the route to verify. Check that an updater or signature policy does not prevent the modified copy from running.

The [type-2 AppImage runtime](https://github.com/AppImage/type2-runtime) is itself part of every resulting image. Its [licence file](https://github.com/AppImage/type2-runtime/blob/main/LICENSE) identifies MIT code plus statically linked musl, libfuse, squashfuse, zstd and zlib with their own terms, including libfuse's LGPL terms. Pin and inspect the **actual runtime binary/source** and include its applicable notices, source and replacement obligations in the artifact review. [appimagetool is MIT licensed](https://github.com/AppImage/appimagetool/blob/main/LICENSE), but its tool licence does not license the image payload. The [current appimagetool README](https://github.com/AppImage/appimagetool) says it downloads the latest runtime unless a local runtime is supplied; use an explicitly pinned, hashed `--runtime-file` (or `APPIMAGETOOL_RUNTIME_FILE`) to prevent a moving binary input. The [linuxdeploy Qt plugin](https://github.com/linuxdeploy/linuxdeploy-plugin-qt) can package Qt 6 and scan embedded QML via `QML_SOURCES_PATHS`; its default plugin choices still require review against the resulting file list.

## Reproducible next experiment and release evidence

At the time of this earlier audit, no `appimagetool`, `linuxdeploy`, `linuxdeploy-plugin-qt` or `patchelf` was installed in the available tool paths; only `mksquashfs` was present. The [release build](release-packages.md) downloads pinned, hashed tool/runtime inputs without changing system packages. The original proposed experiment was:

1. Build the release Quick executable from clean Ubuntu 26.04 dependencies with `BUILD_TESTING=OFF`, no `RPATH`/`RUNPATH`, and the chosen release scanner/codec settings. Record its SHA-256 and `readelf -d` output.
2. Use a pinned `linuxdeploy` and pinned Qt plugin, or an equivalent reviewed staging script, to create `AppDir` from that binary and a desktop file. Point `QML_SOURCES_PATHS` at `apps/daw_quick` because QML is embedded. Explicitly request both X11 and Wayland client platform support. Stage `qt.conf` and a launcher with only relative AppDir paths. Do not copy every local Qt plugin or bundled system library by default.
3. Generate a sorted file list with SHA-256, ELF `DT_NEEDED`, dynamic loader and `RUNPATH`, package/source/notice mappings, QML import resolution and plugin load traces from the **staged AppDir**. Inspect all non-Qt libraries and the Qt third-party closure too. Reject host or user-cache absolute paths.
4. Build with a pinned, hashed type-2 runtime: `appimagetool --runtime-file /absolute/pinned/runtime AppDir output.AppImage`. Hash and extract the image; compare extracted files with the reviewed AppDir manifest. Record runtime/tool versions and licences.
5. Run extracted `AppRun` and the image on clean Ubuntu 26.04 x86-64 Wayland and X11 targets, with normal and deliberately incompatible host Qt installs. Exercise welcome, create/reopen, folder picker, playback, import/export and support smoke. Capture `QT_DEBUG_PLUGINS=1` and `QML_IMPORT_TRACE=1`; verify all loads come from intended image paths except reviewed system exclusions.
6. Replace one bundled Qt shared library with an ABI-compatible modified build and repeat startup and functional smoke. Repeat for bundled LGPL platform/QML plugins. Publish full replacement, source/offer and notice instructions, then audit a real release candidate's complete payload before distribution sign-off.

The older local observation can be repeated with `readelf -d build/package-release2/apps/daw_quick/oscillate`, `ldd` on that file, and `QT_QPA_PLATFORM=offscreen QT_DEBUG_PLUGINS=1 QML_IMPORT_TRACE=1 ... --create <disposable-folder> --smoke`. The [release AppImage](release-packages.md) has an exact file set, but clean-target compatibility and legal compliance remain open.
