# Named project revisions

**Requirements:** PRD §§8, 18, 21; FS-03 PM-03–PM-05, PM-08; ADR-0004.

The persistence API can now name the generation selected by a validated `CURRENT` pointer, list named revisions and load one by its display name. `AUTOSAVE` never becomes a named revision. Names are case-sensitive, 1–64 byte ASCII labels made from letters, digits, spaces, `_`, `-` and `.`; leading/trailing spaces and `.`/`..` are rejected. This deliberately narrow v1 character policy can be widened with an explicit normalization and duplicate-name decision. A display name never becomes a path segment. Each pointer lives at `state/revisions/<random-hex-id>` and contains a strict `name`/`generation`/`sha256` JSON object. `CURRENT` and `AUTOSAVE` keep their existing two-field pointer format; the manifest schema is unchanged.

The sole writer validates `CURRENT`, the writer lock, and duplicate names before staging a pointer file. It flushes the file, renames it without replacement, then flushes `revisions/`. A failure before rename leaves an incomplete temporary file that the listing reports but never treats as a committed name. A fault after rename or a final directory flush failure returns `SaveStatus::uncertain`; on reopen the pointer may exist or be absent. Naming leaves `CURRENT`, `AUTOSAVE`, source assets and user renders untouched.

Listing scans at most 1,024 directory entries and validates at most 256 complete targets, with 64 MiB cumulative manifest-read and decoded-state budgets. Exhausting a bound returns `resource_exhausted`, never a partial list. It validates pointer grammar, name, checksum, target generation and explicit-save kind. Incomplete, malformed, stale and duplicate entries appear in the returned issue list; a duplicate name selects neither pointer. Loading an issue-bearing name fails. The tests cover two named generations across save/autosave/reopen, exact path shape, duplicate names, interrupted publication, malformed and stale pointers, a symlink entry, invalid names, directory replacement and the validated-entry cap.

This is the storage foundation. The UI does not yet offer revision naming or selection, there is no rename/delete command, and generation pruning must protect every valid named target when implemented. Listing may need a worker for large projects. A hostile process that mutates the directory between validation and publication remains outside the atomic namespace guarantee; controlled project directory ownership and filesystem/power-loss qualification remain release gates.

Focused GCC, Clang and ASan/UBSan persistence tests pass, as do formatting and targeted tidy. In the optional-codec coverage build, the two persistence tests cover 1,817 of 2,110 executable persistence lines (86.1%). This remains below the 95% risk-based persistence target; untested syscall failure and malformed-input branches need separate fault/fuzz work, not coverage-only fixtures.
