# Aligned isolated-track WAV stems (bounded slice)

Requirement AM-06 calls for processed stems including inserts, routing effects and tails. The project model now persists main routes, groups, returns and sends. This slice renders those routes and gains plus one enabled native EQ on one audio track. Other track/bus inserts and sidechains remain outside this slice, so it does **not** satisfy the full AM-06 requirement.

`render_wav_stems` writes one stereo WAV for every audio or instrument source track into a new directory. Each file is named `track-<stable track UUID>.wav`; bus-only tracks have no independent source stem. The tap isolates one source before its saved main/send routes, applies the one supported track EQ on its owning audio track, then applies the existing master EQ/compressor/reverb chain. Route gains and downstream paths are included, and processor state is fresh for each stem. All stems retain the full project extent and the same bounded EQ and master-chain tails, even when the selected track ends earlier or is silent. The optional [output-rate adapter](output-sample-rate.md) converts each completed stem to the same selected rate and duration. No other source track leaks into the selected stem. Soloing into a nonlinear master compressor means stem summation need not equal the master. VST3 inserts and unsupported saved automation are rejected explicitly because the offline graph cannot render them; they are never silently omitted. All normal master limitations remain, including unwarped clips and native sampler instruments only.

The caller must supply the same active live revision evidence or an exclusive stopped-export authority as for a master. Each WAV is rendered and fsynced in a private sibling directory. On success the directory is fsynced and atomically renamed to a **new** target with Linux `RENAME_NOREPLACE`, then the parent is fsynced. Existing targets are never overwritten. A pre-publication failure removes the private files and leaves no partial target. A parent fsync failure after rename returns `durability_uncertain` because the directory may be visible but its durability cannot be proven. The API reports only the bundle publication result; a future export report must record per-stem format, revision, tap point and warnings.

The implementation compiles the MIDI plan and computes the global extent once, then opens and prepares only the selected source track per stem through the common offline renderer and shared routed mixer. It still traverses the track list and constructs a fresh route graph and master-effect runtime per stem. Source/clip/instrument limits apply; large-scale stem throughput qualification remains open. Full processed stems still need explicit insert/sidechain tap points, nonzero delay compensation, and broader audio-correctness fixtures.
