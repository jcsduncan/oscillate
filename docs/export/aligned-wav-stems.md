# Aligned isolated-track WAV stems (bounded slice)

Requirement AM-06 calls for processed stems including inserts, routing effects and tails. This slice renders saved main routes, groups, returns, sends and gains, built-in effect chains on source and bus tracks, and direct sidechain detectors ([sidechain stems](sidechain-stems.md)). It does **not** satisfy the full AM-06 requirement.

`render_wav_stems` writes one stereo WAV for every audio or instrument source track into a new directory. Each file is named `track-<stable track UUID>.wav`; bus-only tracks have no independent source stem. The tap isolates one source before its saved main/send routes, applies its track's built-in effect chain, then the saved master chain. Route gains and downstream paths are included, and processor state is fresh for each stem. All stems retain the full project extent and the same bounded effect and master-chain tails, even when the selected track ends earlier or is silent. The optional [output-rate adapter](output-sample-rate.md) converts each completed stem to the same selected rate and duration. No other source track leaks into the selected stem. Soloing into a nonlinear master compressor means stem summation need not equal the master. VST3 inserts and unsupported saved automation are rejected explicitly because the offline graph cannot render them; they are never silently omitted. All normal master limitations remain.

The caller must supply the same active live revision evidence or an exclusive stopped-export authority as for a master. Each WAV is rendered and fsynced in a private sibling directory. On success the directory is fsynced and atomically renamed to a **new** target with Linux `RENAME_NOREPLACE`, then the parent is fsynced. Existing targets are never overwritten. A pre-publication failure removes the private files and leaves no partial target. A parent fsync failure after rename returns `durability_uncertain` because the directory may be visible but its durability cannot be proven. The API reports only the bundle publication result; a future export report must record per-stem format, revision, tap point and warnings.

The implementation compiles the MIDI plan and computes the global extent once, then opens and prepares the selected source track per stem, plus any sidechain detector tracks it keys, through the common offline renderer and shared routed mixer. It still traverses the track list and constructs a fresh route graph and master-effect runtime per stem. Source/clip/instrument limits apply; large-scale stem throughput qualification remains open. Full processed stems still need explicit insert tap points and broader audio-correctness fixtures.
