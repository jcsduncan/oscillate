# JACK real-time master capture

The Quick export dialog has a separate **JACK real-time WAV 32F** action under *More exports*. It captures the final stereo master from bar 1 at the project sample rate. The selected end bar (exclusive) is the *content end*; the selector uses the shared meter and tempo maps. The existing offline master and stem actions retain their separate tail policies.

## Tail policy

The file covers project samples `[0, end + tail)`:

- **Source cut.** From the content end, audio source slots deliver silence. This covers the rest of a clip that crosses the end and any clip that starts later, including processed (warped or pitched) clips. Prepared native synths and samplers instead receive note-off for held notes at the exact content-end sample, suppress note-ons at or after that sample, and keep rendering their releases. The cut happens before track inserts, sends and routing. An audio clip that is still sounding at the end stops abruptly at the source; its fade-out is not applied early.
- **Ring-out.** The graph, its processor histories, routing gains and automation keep rendering after the cut. Only what was already inside a processor at the end can reach the file.
- **Bound.** `tail` comes from the prepared graph and source instances: each native synth's fixed release bound, each prepared sampler patch's fixed release frames, native EQ settling estimate (about -180 dB per section), native reverb's -90 dB bound (0 when fully dry), and 0 for compressor and limiter, which keep gain state only. Serial stages sum; parallel routes take the longest path. The total is capped at ten seconds. Native synth parameter automation and sampler level automation are refused because the prepared fixed-control release contract does not cover them.
- **Output latency.** The run starts its transport at sample 0 and skips the prepared route and terminal master latency (`master_output_latency_frames`, for example a limiter's lookahead) before capturing. File frame 0 is project sample 0, as in the offline master. The device hears the same stream, and goes silent after the last captured frame.

The bound and source cut are known only for these shapes. Each of the following fails before JACK or the output file opens. Some failures occur during private graph or source preparation. The rejected run releases its playback reservation:

- an enabled VST3 audio effect without an exact fixed-tail qualification for its prepared instance;
- a VST3 instrument source;
- an unbound instrument track with MIDI clips, because its release cannot be prepared;
- an enabled convolution insert, which routed preparation also rejects;
- a tail sum above ten seconds.

Use the offline master for these projects. A bypassed VST3 slot contributes no tail and does not block the action.

The run prepares its own revision-pinned routed graph, source bank, processor/plugin instances and transport cursor before opening a JACK client. It does not consume or seek the live playback cursor. A dedicated callback-to-worker ring records only final master frames. The worker waits for the exact interval and hands the prepared run back to the serialized Quick control thread. That thread checks cancellation and the current project revision, then joins the JACK callbacks and drain worker before validating and atomically publishing the temporary WAV. Project commands cannot interleave with this final check and publication. Cancelling, a short interval, device xrun, callback over-period block, source underrun, render fault or changed project revision prevents publication and leaves an existing target intact. Finishing a long WAV may briefly pause the UI during disk sync; a separate publication sequencer is future work.

This action requires a JACK-enabled build, an available JACK server at the project rate and the selected buffer, a stopped project, float32 WAV, and the project output rate. Unsupported saved graph/plugin routes fail in the existing routed preparation with their reason. JACK output ports are not auto-connected by this path; audible monitoring depends on connections made in a JACK patchbay. PipeWire's output status currently lacks the required xrun evidence, so this action makes no PipeWire capture claim.

Local contract test `quick_realtime_export_contract` uses a fake JACK server and a saved/reopened managed WAV project. It checks a non-block-aligned exact endpoint for an insert-free project (no tail or latency), callback allocations, control-thread stop and publication, xrun preservation of a pre-existing target, and cancellation preservation. A parity case in that test saves and reopens a managed tone project with a track peaking EQ and a master compressor. It compares an independent offline float32 master render with fake-JACK renders at 64 and 128 frames. The endpoint at 4,001 frames falls mid-period for both buffer sizes. The test checks the frame count (the end plus the EQ tail bound), the onset at the source's first non-silent frame, and a peak window showing that both inserts shaped the reference. Every frame before the endpoint must match within 1e-6 (-120 dBFS). That tolerance allows a few float rounding differences from the offline 1,024-frame partition, but fails a one-sample shift or block-rate parameter change. A repeated 64-frame render must be byte-identical. In the second half of the EQ tail the offline render still plays the tone, while both fake-JACK renders stay below 1e-4. Disabling the source cut fails this check. The checks run without callback allocations. Observed on 18 October 2026 (GCC 15.2, `quick` preset): offline peak 0.686511 and maximum difference 0 for both buffer sizes.

A tail case saves and reopens a project with one 3,000-frame tone clip, a later copy of that clip starting after it, a master reverb (wet 0.4, 0.4 s decay) and a 5 ms master limiter. The content end, at 2,501 frames, falls mid-clip and mid-period. The reference is an independent offline master render of a second project whose only source is the same tone truncated to 2,501 frames, with the same inserts. A source frame or later clip past the end, a dropped tail, or an uncompensated limiter delay breaks the match. The test checks the following:

- the prepared output latency is 240 frames;
- the length is the end plus the 30,919-frame reverb bound, which equals the offline reference length;
- the onset is at frame 300;
- reverb ringing is audible 10-100 ms after the end;
- the full project's offline render still has tone after the end;
- every frame matches the reference within 1e-6 at 64 and 128 frames.

Observed on 18 October 2026 (GCC 15.2, `quick` preset): tail peak 0.0649 and maximum difference 0 for both buffer sizes. A rejection case checks each unsupported shape above and that a rejected run opens no JACK client, writes no target and releases the project gate. Export test `export_jack_realtime` checks the latency-offset window with a fake master: the capture starts mid-period, and device output stops after the last captured frame.

The native-synth case adds a saved/reopened Prism project with a note crossing a 4,000-frame content end and a second note starting later. The prepared source inserts note-off at 4,000, blocks the second note, and keeps the exact player running for its declared release. The fake-JACK WAV at 64 and 128 frames matches an independent offline project whose note ends at 4,000 and has no later note; release remains audible, duration is exact, repeat bytes agree, callback allocations stay zero, and an xrun leaves a prior WAV intact. This evidence covers the prepared Prism settings in the fixture, not every native patch or physical JACK deadlines. Native synth automation and VST3 instrument release remain unsupported in real-time export.

The sampler case uses a saved/reopened managed source with a held note crossing the same 4,000-frame end, a later note, and a fixed 2,000-frame release. The same prepared sampler receives the boundary note-off and renders through its track effects. Fake-JACK exports at 64 and 128 frames are compared with an independent offline project whose held note ends exactly at 4,000 and whose later note is removed. The test checks audible release, exact duration, byte-identical buffer-size renders, zero callback allocations, xrun preservation of a prior WAV, and rejection of sampler level automation before JACK opens. This is a fixed-control sampler subset; live runtime offers during a private export, arbitrary source loss and physical deadline performance remain outside this test.

## Open contracts

- **VST3 tails.** `RoutedPlaybackControl::prepared_route_tail_receipt(expected_revision, export_end)` copies the initial private graph's prepared latency plan, master ID and one node-tail receipt per route node. It can run immediately after `submit_current()`, before the first callback opens JACK, or while that same initial revision is active. It refuses a newer model revision, graph handoff, pending native/manual edit, processor fault, unmatched saved slot, unbounded instrument release or VST3 automation. Native EQ/reverb bounds come from the exact settings used to construct their runtimes; compressor and limiter add no drain beyond separately accounted output latency. A VST3 effect contributes its bound runtime's `finite_tail_frames` only when the provider also marks that binding `fixed_tail_qualified`. Binary-specific qualification remains required; a plugin's declared tail alone is insufficient. Later graph revisions require a fresh dedicated export control. The focused `application_prepared_route_tail` test covers the pre-callback receipt, group/send routing, native tail semantics and rejection paths; this is not physical JACK or third-party tail-accuracy evidence.
- **Prepared tail planner.** `exporting::plan_realtime_tail_frames` now accepts one explicit finite-tail receipt per node in the prepared `RoutingLatencyPlan`. The caller sums serial stages within a node; the planner takes the longest route through sends and buses, rejecting unknown tails, incomplete or ambiguous receipts, disconnected topology and a bound above the caller's cap. It does not open JACK or an output file. The routed-control owner must produce the receipts from the same revision-pinned processor instances that it publishes; saved metadata or a second plugin instance cannot stand in for the running export graph. It must account for native stages and bound VST3 effects in saved chain order, including bypass as zero, then verify the graph revision before handing the plan to Quick. `getTailSamples()` is a plugin declaration at preparation time, not proof that the bound remains valid after tail-affecting automation or a plugin restart request. Admit only a qualified fixed-tail control set, or reject that effect for real-time export. Keep VST3 instruments excluded until source note-off and release bounds are specified. Quick calls the planner after graph preparation and before JACK/output creation, then uses that bound as the capture extent. The existing callback deadline, xrun, source-health and atomic-publication checks remain mandatory.
- **Capture API.** `JackRealtimeWavExport::begin_with_tail_plan` checks that its requested WAV frame count equals the content interval plus the prepared graph's tail bound. It rejects an unknown tail or shortened interval before opening a capture file or JACK client. `export_realtime_tail_plan` tests a serial finite VST3-style tail against a parallel path and rejects unknown, missing, disconnected and over-budget cases. `export_jack_realtime` proves that unknown or omitted tail frames leave the target and fake JACK unopened, and that a finite eight-frame receipt extends the published interval. The test uses a synthetic receipt, not a real VST3 binary or physical device; real plugin tail accuracy and deadline qualification remain separate gates.

### Quick integration status

`RealtimeExportRun::begin` now prepares its private graph, obtains the exact
revision-pinned route receipt, plans the longest bounded tail, sizes the
source-cut and capture intervals, then calls `begin_with_tail_plan` before
opening JACK. A rejected plan retires the private graph and releases the
project transport token. The Quick export panel now describes the source cut
and supported effect-tail drain accurately. The native EQ/reverb/limiter
fake-JACK parity test and the prepared-route test pass in the main build.

A real VST3 effect remains rejected because the production provider has no
binary-specific fixed-tail qualification. To close this path, qualify a
particular VST3 binary and control set, then prove its tail in the Quick
fake-JACK app test at both buffer sizes: audible tail frames, exact duration,
zero callback allocations, and an unchanged prior output on unknown tail or
xrun. VST3 instruments still need a note-off and release bound.
- **Native instrument releases.** Before JACK opens, the private `RoutedAudioSource` rewrites each native synth player's MIDI event plan at the selected end. It retains events before the end and saved note-offs at the end, adds note-offs for held voices at the end, and removes later note-ons. The callback uses the same preallocated event reader as playback. The prepared-route receipt takes the release bound from that exact player, rejects unconfigured or automated players, and sums the source bound before its insert chain. Audio/sampler source slots still cut to silence; native synth slots keep their release. The export never uses a second synth instance to probe the tail.
