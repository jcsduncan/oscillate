# Offline output sample rates

The export renderer mixes and processes at the project sample rate. Only after the final native-effect block does a stereo, stateful output converter change the rate. This leaves tempo-map events, MIDI, clip placement, effect settings and tail accounting on the same project clock as playback. Each WAV master, WAV stem and codec master has a `sample_rate` option; zero keeps the project rate. The supported selections are 44,100, 48,000, 88,200 and 96,000 Hz. Expected output frames are the project-rate rendered duration scaled by the rate ratio and rounded to the nearest frame. For certain fractional endpoints, libsamplerate produces one frame fewer than this rounded duration; that single terminal frame is silence outside the project mix. At most one extra filter frame is discarded. A larger deficit or surplus fails the export. Conversion is worker-only, bounded in 1,024-frame input blocks and uses one converter instance for the entire render. Integer dither and encoding follow conversion. A failed conversion leaves the previous master or stem bundle unpublished/unchanged.

Build with `-DOSCILLATE_BUILD_EXPORT_RESAMPLER=ON` and the `libsamplerate` development package to enable a different output rate. A build without the library still exports at the project rate and returns an explicit unsupported error for conversion. CMake requires the header and shared library when the option is on. Packaging must include or depend on that shared library and ship its BSD-2-Clause notice. The dependency is not used on the audio callback. The existing MP3 writer supports only 44.1 and 48 kHz; its higher-rate requests fail before publication.

The Qt Quick export dialog shares one output-rate selection across master and WAV-stem actions. It defaults to Project rate whenever a project opens. Explicit choices are disabled when conversion is unavailable, except a choice equal to the project rate. MP3 selections above 48 kHz are disabled for the master; a previously selected high rate remains visible with an explanation when the master format changes to MP3. Stem export remains available at that rate because it writes WAV. The bridge also rejects an invalid master selection before starting an export worker.

## Dependency choice and evidence

| Candidate | Quality and cost | Redistribution | Decision |
| --- | --- | --- | --- |
| [libsamplerate](https://github.com/libsndfile/libsamplerate) | Stateful sinc modes, including a documented best-quality band-limited mode. The [full API](https://libsndfile.github.io/libsamplerate/api_full.html) supports chunked streams; its [FAQ](https://libsndfile.github.io/libsamplerate/faq.html) explains filter transport delay and why one-shot conversion on successive blocks is wrong. Best quality costs more CPU than its faster modes. | [BSD-2-Clause](https://github.com/libsndfile/libsamplerate/blob/master/COPYING), notice required. Ubuntu provides `libsamplerate0` and `libsamplerate0-dev`. | Selected for the optional offline adapter. The adapter pins `SRC_SINC_BEST_QUALITY`; quality does not silently degrade. |
| [SpeexDSP](https://github.com/xiph/speexdsp) | Has a configurable sinc resampler and real-time oriented API; quality and CPU need a local comparative measurement for this use case. | [BSD-style licence](https://github.com/xiph/speexdsp/blob/master/COPYING). | Viable alternative if measured export throughput or audio quality warrants a change. |
| [SoX Resampler](https://github.com/chirlu/soxr) | High-quality rate converter; would need the same local quality and throughput qualification. | [LGPL-2.1](https://github.com/chirlu/soxr/blob/master/COPYING.LGPL) adds distribution obligations. | Not selected under the PRD's preference for permissive licences. |

The local quality oracles check an independently generated 440 Hz source at every converted rate against the same physical frequency on the output clock and check that a 23 kHz input tone is suppressed when converting 48 to 44.1 kHz. Tests also check exact header duration, deterministic repeat bytes, stale-revision preservation, aligned converted stems and reverb tails. These are correctness checks, not a listening or reference-hardware qualification.

A local, uninstrumented C++20/GCC 15.2 benchmark on an Intel i7-10700K used libsamplerate 0.2.2 with a 30-second stereo 440 Hz stream, 48 to 44.1 kHz. The best-quality converter took 1.48, 1.50 and 1.50 seconds with 64-, 128- and 1,024-frame input blocks, respectively (about 20 times real time). The medium mode took 0.36, 0.40 and 0.38 seconds (about 76–83 times real time). This measures only conversion CPU, not project rendering, filesystem output or plugin workload; it justifies keeping the best mode for offline export at this stage. The converter is created once and its work buffers have fixed size, so its per-block path does not allocate in our code. Before release, run representative listening material, multitrack throughput and passband/alias measurements on the reference machine, and record binary/SBOM obligations. The output converter does not resample mismatched **source media**; that remains an explicit source-preparation limitation.
