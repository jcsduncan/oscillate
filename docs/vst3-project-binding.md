# VST3 project binding slice

**Scope:** PI-04 control-side restoration from a schema-1.7 `Vst3PluginInstance` and a fresh successful scanner result. This does not insert a processor into the audio graph or implement a plugin browser.

`bind_vst3_project_effect` accepts a saved instance and an explicit `ScanResult`. It validates the saved SHA-256 against the freshly scanned binary, matches the class ID, vendor, name and version, and passes that scanned class and binary receipt to `load_verified_vst3_effect`. The loader checks canonical binary identity again immediately before and after module load. The saved `bundle_path` is advisory and is never passed to a loader. A relocated bundle can bind only after an explicit fresh scan produces the same binary digest and class identity. `missing=true` does not block this explicit recovery; the function does not change the project flag.

The host is created off the callback. The binding validates saved parameter references against discovered IDs and returns unresolved IDs and a diagnostic while leaving the durable references intact. It restores the bounded opaque component state **before** activation. Failed restoration returns no live effect and never activates the host. On success, the caller owns the active `LoadedVst3Effect`, including module lifetime, and must suspend and destroy it off the callback after render quiescence.

When opaque component state exists, it is restored to the processor and controller before activation. Saved normalized parameter references remain recovery metadata; they are not layered over that state. Unknown IDs remain in the unchanged project record and are returned in `unresolved_parameter_ids` with a diagnostic. When component state is absent, verified automatable references are staged on the controller, then flushed to the processor before the first audible block. An unavailable or rejected required value fails the binding without publishing an effect. The caller must keep binding off the audio callback and present unresolved IDs to the user.

The connected synthetic fixture now follows the Quick editor's save sequence: stage an edit, flush it to the processor, suspend, capture the resulting component state, bind a fresh instance, and inspect its first audible block and restored latency. The saved value survives in that fixture. It also checks that a deliberately conflicting reference does not override valid opaque state and that an unknown reference remains reported and durable. This does not prove every third-party plugin serializes all parameters in `IComponent::getState`; plugins that omit a parameter need a separate compatibility finding and an explicit restoration policy. Applying every saved reference over opaque state by default would change valid plugin state when the two disagree.

Binding does not update model state or bypass the project's command/undo path. Its callers must present failures as missing or incompatible project placeholders and retain the original project data for retry or relink. Later UI and graph adapters consume the binding result under their own publication and thread-safety contracts.

## Integration and evidence

When the optional VST3 scanner is enabled, add `add_subdirectory(project_binding)` after `bundle_loader` in `src/plugins/CMakeLists.txt`, and add `add_subdirectory(project_binding)` to `tests/plugins/CMakeLists.txt`. The dedicated target depends publicly on `oscillate::vst3_bundle_loader`. It adds no runtime dependency beyond the existing VST3 loader.

The synthetic gain fixture verifies restored sample output, advisory-path nonuse, a rescanned relocation, mismatch rejection before module load, byte changes after scan, invalid state rejection before activation, unresolved-reference reporting, project immutability, and module teardown order. The optional VST3 build passed 43/43 CTests on GCC; the focused binding test also passed Clang and ASan/UBSan. Clang tidy and format passed for the new files. The binding implementation measured 49/50 executable lines (98%) in the focused GCC coverage run. The activation-failure branch remains unexercised because the existing synthetic bundle has no activation failure mode; activation failures still return no live effect.
