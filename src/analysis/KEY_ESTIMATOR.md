# Worker-only source key suggestion (PA-01 slice)

`analyze_key` returns a source-relative **suggestion**, or an explicit unknown result (`key == nullopt`, confidence zero). It never changes the project key, analysis corrections, a clip setting, or the audio graph. The caller supplies a stable source key and request generation and must compare both, plus source version, again before installing a result. Cancellation and decoder failure return no partial estimate. Analysis is allowed only on a processing worker with a verified `AudioReader`; the audio callback must never call it.

## Method and limits

The analyzer samples at most 1,024 evenly spread 16,384-frame Hann windows by default, reads bounded mono/stereo PCM, and transforms each window with the shared complex radix-2 FFT (`src/analysis/dsp/fft.hpp`). It aggregates local spectral peaks between 55 Hz and 2 kHz (bass and harmony, little percussion) into normalized pitch-class energy, then ranks the 24 major/minor keys by Pearson correlation with the KeyFinder profiles (Sha'ath, 2011). It requires enough useful windows and supported pitch classes, a minimum correlation and a lead over the runner-up. Thus a sustained single chord, short material, silence, noise and relative-key ambiguity return unknown in the fixtures. Confidence is a bounded ranking margin, **not** a calibrated probability of correctness. Compatibility entries express the relative key and same-mode fifth/fourth neighbours; they are harmonic suggestions, not transposition instructions or evidence that those keys occur in the source.

The shared FFT is a fixed-size reference transform, not a wrapper around PFFFT. Before adopting this as production musical-key analysis, compare accuracy and CPU use against licensed key-analysis candidates on a labelled music corpus. FFT substitution must preserve the independent key fixtures and uncertainty behavior.

The test oracle synthesizes exact-frequency major/minor triad progressions without calling the estimator's FFT or template scorer. It covers C and D major, A minor with a chromatic dominant, harmonics, single major/minor chords, a mixed relative-key passage, silence, pseudorandom noise, exact-window input, cancellation and truncated audio. These synthetic fixtures **do not qualify real recordings**: percussion, tuning drift, modulation, sparse arrangements, dense distortion, lower-register bass, vocals, different temperaments and relative-key ambiguity may be wrong or unknown. No UI or persisted project schema currently consumes the suggestion.

## Bounded resource cost

The transform uses one 16,384-frame stereo input array and one 16,384-bin complex array, roughly 384 KiB of fixed scratch, plus small result data. A window limit outside 4–1,024 is rejected as invalid; the default is 1,024. Work is O(window count × 16,384 log 16,384), independent of source duration except for evenly spaced seeks. Input reads and FFT windows have cancellation checks. A decoder call itself is governed by that decoder's contract and cannot be interrupted while it is blocked.

On the local x86-64 machine, GCC Release, 48 kHz mono, a 60-second generated 30-chord passage with an explicit 256-window budget took **249 ms** inside `analyze_key`; the standalone benchmark process peaked at **9.8 MiB RSS**, including its generated fixture buffer and decoder. The default 1,024-window budget costs up to four times that on long material (a 60-second source holds fewer windows than the budget). Reproduce with `oscillate_key_tests --benchmark` in a Release build. This is a worker cost, not callback latency or reference-hardware qualification. At 64/128-frame audio block sizes the callback cost is exactly zero because this code is not called from the callback.

## Integration contract

Schedule after managed import using the existing processing executor with source identity/version and a new generation. Supersede stale requests; store generated result separately from user key corrections. A consumer may show the tonic/mode and compatibility suggestions only when `key` is present, with an explicit confidence and a manual accept action. Reanalysis must never overwrite manual corrections. If persisted, add a versioned analysis payload and migration tests before wiring the model or UI. The current implementation has no project schema, UI or cache integration.
