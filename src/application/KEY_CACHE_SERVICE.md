# Managed-source key suggestion service

`load_key_suggestion` is a worker-only composition of verified managed-source open, the bounded key estimator and the disposable key payload codec. It uses a `source_analysis` semantic cache descriptor with algorithm ID `musical-key-suggestion`, version 1, quality 1, and an eight-byte little-endian `max_windows=256` setting. The descriptor includes immutable encoded source digest, byte length and encoding. A changed encoded source is a cache miss even when sample rate and frame count match; generation does not affect cache reuse.

The service verifies the managed source before a cache lookup. A valid cache hit is decoded against the current source key and decoded metadata and adopts the supplied request generation. Corrupt or missing entries are regenerated; cache read/write errors become a warning when analysis can still succeed. A cancelled request returns a conflict and never returns a partial estimate. The result may explicitly be unknown (`estimate.key` absent, confidence zero), which is a valid reusable cache value. No method in this service runs on the audio callback.

A consumer must rederive `key_cache_key(current_source)`, compare it with `estimate.identity.source_key`, check the current request generation and claim the cancellation ticket **after** this worker returns and before publishing any suggestion to project/UI state. The service cannot know whether the project source changed while it was working. Generated key suggestion, manual correction and acceptance state must be stored separately; this service neither edits nor persists them. Its quality and CPU limits are described in `src/analysis/KEY_ESTIMATOR.md`.
